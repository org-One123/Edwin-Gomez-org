# 📊 Rúbrica de Evaluación del Proyecto

| Criterio | Excelente (5.0) | Aceptable (3.5) | Deficiente (1.0) |
| :--- | :--- | :--- | :--- |
| **Estructura de Git** | Respeta la nomenclatura de ramas, usa `CODEOWNERS` y maneja PRs correctamente. | Crea ramas pero los mensajes de commit o la estructura no son claros. | Trabaja directamente sobre `main` sin control de versiones. |
| **Funcionalidad** | La app cumple con todos los criterios de aceptación sin errores. | La funcionalidad principal sirve pero presenta errores menores. | La app no compila o no cumple los requerimientos base. |
| **Documentación** | Archivos `.md` completos, detallados y bien formateados. | Documentación básica o incompleta. | Ausencia de documentación en la carpeta `docs/`. |
| **Calidad de Código** | Código limpio, modular y siguiendo las buenas prácticas. | Código funcional pero desorganizado o redundante. | Código duplicado, inapropiado o con fallos graves. |
